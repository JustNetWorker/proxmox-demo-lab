# Стенд демэкзамена в Proxmox из qcow2

Скрипт создаёт восемь **новых выключенных ВМ**, импортирует установленные ОС из Google Диска, задаёт им имена, CPU, RAM и сетевые адаптеры. Устанавливать ОС заново из ISO не требуется. Ideco импортируется вместе с экспортированным EFI-диском.

## Запуск в Shell узла Proxmox от root

```bash
curl -fSL https://raw.githubusercontent.com/JustNetWorker/proxmox-demo-lab/main/bootstrap.sh -o /root/demo-bootstrap.sh && bash /root/demo-bootstrap.sh --menu
```

Меню: **1** — план, **2** — создание стенда, **0** — выход.

План напрямую:

```bash
bash /root/demo-bootstrap.sh --deploy-plan
```

Создание напрямую:

```bash
bash /root/demo-bootstrap.sh --deploy
```

Другой диапазон номеров и хранилище:

```bash
bash /root/demo-bootstrap.sh --deploy --base-id 300 --bridge-base 301 --storage local-lvm --uplink vmbr0
```

Кэш образов по умолчанию `/var/lib/vz/demo-images`. Если там мало места, укажи `--image-dir /путь/на/другом/диске/demo-images`. Источники скачиваются один раз, сверяются с локальными контрольными суммами и остаются для повторного развёртывания. Google Drive может ограничивать публичные скачивания; ошибка скачивания останавливает создание до изменения сети и ВМ.

## Ресурсы и топология

| VMID | Имя | ОЗУ | Ядра | Системный диск базы | Адаптеры по порядку |
|---|---|---|---|---|---|
| 200 | ISP | 1 ГБ | 1 | 32 ГБ | vmbr0, vmbr201, vmbr202 |
| 201 | HQ-RTR | 2 ГБ | 2 | не меньше 10 ГБ | vmbr208, vmbr201, vmbr203 |
| 202 | HQ-SW | 1 ГБ | 1 | 32 ГБ | vmbr203, vmbr204, vmbr205 |
| 203 | HQ-SRV | 2 ГБ | 1 | 32 ГБ | vmbr204 |
| 204 | HQ-CLI | 2 ГБ | 2 | 32 ГБ | vmbr205 |
| 205 | BR-RTR | 2 ГБ | 2 | не меньше 10 ГБ | vmbr209, vmbr202, vmbr206 |
| 206 | BR-FW | 6 ГБ | 4 | 160 ГБ + EFI | vmbr207, vmbr206 |
| 207 | BR-SRV | 2 ГБ | 1 | 32 ГБ | vmbr207 |

Фактическая ёмкость импортированного диска берётся из qcow2: большие диски не уменьшаются. EcoRouter увеличивается до 10 ГБ, если его диск меньше; увеличение разделов внутри гостя выполняется отдельно.

Всем ВМ вместе нужно **18 ГБ ОЗУ плюс память Proxmox**. На узле с 16 ГБ запускай необходимые машины по очереди. Скрипт не запускает весь стенд автоматически.

`vmbr0` — существующий мост к домашней сети/Интернету. Остальные девять мостов создаются без физических портов и IP узла. На EcoRouter net0 — управление, net1 — ISP, net2 — LAN. На BR-FW net0 — сеть BR-SRV, net1 — сеть BR-RTR. ALT/Ideco получают VirtIO, EcoRouter — e1000.

Скрипт задаёт **названия в панели Proxmox**. Имена внутри ОС, IP-адреса, пароли, VLAN, маршрутизация, DNS и службы модуля остаются такими, как в загруженных образах. Импорт чистой ОС сам по себе не выполняет первый модуль экзамена. Автоматическую настройку внутри гостей нужно добавлять и проверять отдельно.

## Образы

[Папка Google Drive](https://drive.google.com/drive/folders/1ZkHbBdzr9-UAWuZ4TGUIs7O5DhCfvKmC)

- `alt-jeos.qcow2`: ISP и HQ-SW;
- `alt-server.qcow2`: HQ-SRV и BR-SRV;
- `alt-workstation.qcow2`: HQ-CLI;
- `EcoRouterOS.qcow2`: HQ-RTR и BR-RTR;
- `ideco.qcow2`: основной диск BR-FW;
- `ideco-efi.qcow2`: состояние UEFI BR-FW;
- `ideco-config.txt`: экспорт конфигурации для восстановления UUID и MAC Ideco.

Если загрузка файла ещё не завершена, не запускай создание. Ссылки на конкретные файлы перечислены в `images.json`. Недостающие ID останавливают запуск. Скачать ISO для этого варианта не требуется.

ALT-базы экспортированы с SeaBIOS и VirtIO SCSI. Ideco — q35, OVMF, EFI 4m без предустановленных ключей Secure Boot. Основной и EFI-диск должны быть из одной выключенной ВМ. Файл конфигурации читается как текст: команды из него никогда не выполняются. Сохраняются UUID SMBIOS и MAC net0 Ideco; RAM и CPU берутся из таблицы выше. Лицензию после импорта нужно проверить в панели Ideco. Исходную и клонированную Ideco с одним MAC не подключай одновременно к одной сети.

При клонировании ALT из общей базы системные идентификаторы и SSH-ключи также копируются. Перед практическим использованием настрой отдельные имена/адреса и уникальные machine-id/SSH host keys для каждой машины. Учётные данные остаются из базовых образов; в GitHub пароли не записываются.

## Проверки и ограничения

Скрипт отказывается заменять существующие VMID, включая контейнеры и ВМ других узлов кластера. Он отказывается использовать уже существующие мосты выделенного диапазона или работать при отложенных изменениях сети. До создания мостов проверяет все qcow2, отсутствие внешних backing-файлов, EFI и доступную ёмкость целевого хранилища. Загруженные образы проверяются `qemu-img check`.

Для `lvmthin` скрипт оценивает объём записанных блоков через `qemu-img map`, учитывает повторное использование баз для нескольких ВМ и добавляет запас: минимум 10 ГиБ или 25% объёма импорта. Размер сжатых qcow2 для этого расчёта не используется. После запуска гостей thin pool будет расти по мере записи: контролируй свободное место и Data%. Для прочих типов хранилищ сохраняется консервативная проверка полной виртуальной ёмкости — около 340 ГиБ плюс запас. На тестовом Proxmox с диском 60 ГБ и пулом 23,75 ГиБ весь стенд может не поместиться; увеличь диск и расширь сам пул `local-lvm`. Контрольные суммы кэша обнаруживают изменения после скачивания, но не являются подписью производителя.

При ошибке новые ВМ и журнал `/root/demo-deploy.XXXXXXXX` сохраняются для диагностики. Скрипт не удаляет их автоматически и не откатывает сеть. Исходные ВМ не заменяются. Повторный запуск на тот же занятый диапазон остановится; выбери новый диапазон или сначала вручную разбери частичное развёртывание.

Проверены синтаксис, план и сценарии импорта на имитированном Proxmox: отказ при занятых ID, импорт основного/EFI диска, ресурсы, адаптеры, отсутствие автоматического запуска. Полное развёртывание и загрузка этих образов на реальном узле пока не проверены.

## Только адаптеры существующего стенда

Старый режим сохранён: `--plan` и `--apply` используют `connect-adapters.sh` и `machines.tsv`, без скачивания и импорта образов. Карта существующих VMID должна соответствовать твоему узлу. Перед изменениями просматривай план.

```bash
bash /root/demo-bootstrap.sh --plan
bash /root/demo-bootstrap.sh --apply
```

## Если Google Drive отказывает в скачивании

Сообщение называет конкретный файл и его ссылку. Причиной могут быть доступ, ограничение Google или временная ошибка — по одному сообщению нельзя точно определить причину. Уже завершённые скачивания сохраняются. Повтори `bash /root/demo-bootstrap.sh --deploy` позже: корректный кэш используется снова, частичные скачивания возобновляются.

Для `ideco-efi.qcow2` опубликованы размер и SHA256, проверенные по текущему публичному файлу. Можно скопировать свой исходный EFI-файл с Mac через SCP в `/var/lib/vz/demo-images/ideco-efi.qcow2`, затем повторить запуск. Скрипт примет его только при совпадении SHA256. Чужие или непроверенные локальные файлы автоматически не принимаются. Контрольная сумма связывает копию с выбранным образом, но не является подписью Ideco.
