# Автоматическое развёртывание учебного стенда Proxmox

Создаёт **новый** стенд: ISP, HQ-RTR, HQ-SW, HQ-SRV, HQ-CLI, BR-RTR, BR-FW, BR-SRV. Назначает имена, процессоры, ОЗУ, диски и сетевые карты. Образы скачиваются из [папки Google Drive](https://drive.google.com/drive/folders/1ZkHbBdzr9-UAWuZ4TGUIs7O5DhCfvKmC).

**Статус: первая версия автоустановщика, полная установка на реальном Proxmox ещё не проверена.** Проверены синтаксис, формирование плана, подготовка профиля на метаданных предоставленных ALT ISO, экранирование пароля и содержимое созданного тестового ISO. В тесте операция xorriso заменена имитацией; это не проверка загрузки ISO. На текущем стенде скрипт не запускался.

## Что установится

- ISP и HQ-SW: ALT p11 JeOS, штатный autoinstall.
- HQ-SRV и BR-SRV: ALT Server 11.0, базовая система.
- HQ-CLI: ALT Workstation 11.1, базовый набор данного ISO с графической оболочкой.
- HQ-RTR и BR-RTR: импорт предоставленного EcoRouterOS.qcow2.
- BR-FW: создание VM с Ideco 23.1.126 ISO, **установка вручную**, согласно выбранному варианту. В этом ISO BIOS-установка не поддерживается, поэтому используется UEFI без Secure Boot.

Установка ОС не является выполнением первого модуля: IP, VLAN в гостях, маршрутизация, DNS, DHCP, VPN и правила Ideco этим скриптом не настраиваются. Лицензию Ideco активируй отдельно.

## Запуск в Shell узла Proxmox

Сначала просмотри план:

```bash
curl -fSL https://raw.githubusercontent.com/JustNetWorker/proxmox-demo-lab/main/bootstrap.sh -o /root/demo-bootstrap.sh && bash /root/demo-bootstrap.sh --deploy-plan
```

Для создания и установки:

```bash
bash /root/demo-bootstrap.sh --deploy
```

Скрипт запрашивает один пароль для ALT root и admin. Пароль не находится в репозитории и не передаётся Google Drive. Образы и компоненты скачиваются без входа в Google. Если Drive исчерпал квоту или закрыл доступ, загрузка останавливается с ошибкой; ограничения не обходятся.

Не закрывай консоль до завершения. Альтернативно запусти в tmux, если он уже установлен. Скачивание занимает время: в папке примерно 16 ГБ исходных образов. Полного обновления Proxmox скрипт не делает; при необходимости устанавливает python3-venv, xorriso и socat из системных репозиториев. Python-библиотеки gdown и pycdlib устанавливаются в отдельное окружение.

## Номера и ресурсы по умолчанию

| VMID | Машина | ОЗУ | Ядра | Диск |
|---|---|---|---|---|
| 200 | ISP | 1 ГБ | 1 | 20 ГБ |
| 201 | HQ-RTR | 4 ГБ | 4 | минимум 10 ГБ, сохраняется больший размер исходного qcow2 |
| 202 | HQ-SW | 1 ГБ | 1 | 20 ГБ |
| 203 | HQ-SRV | 2 ГБ | 1 | 20 ГБ |
| 204 | HQ-CLI | 2 ГБ | 2 | 32 ГБ |
| 205 | BR-RTR | 4 ГБ | 4 | минимум 10 ГБ |
| 206 | BR-FW | 8 ГБ | 4 | 160 ГБ |
| 207 | BR-SRV | 2 ГБ | 1 | 20 ГБ |

Ресурсы BR-FW выбраны с запасом относительно [требований Ideco для виртуальной платформы](https://docs.ideco.ru/pdf/v20/ru-ngfw-general-choosing-hypervisor.pdf); этот документ относится к v20, полные требования именно v23 следует проверить отдельно. Размер диска и память можно изменить в массиве параметров deploy.sh. Это параметры развёртывания, а не подтверждение соответствия конкретному варианту КИМ.

Сумма — 24 ГБ ОЗУ плюс память хоста. На хосте с 16 ГБ нельзя одновременно запустить все машины с этими ресурсами. Скрипт устанавливает ALT по очереди и оставляет машины выключенными; при установке временно даёт серверным ALT 2 ГБ, HQ-CLI 4 ГБ. Нужно освободить не менее 5 ГБ памяти перед запуском и минимум 26 ГБ на local для исходников и одного временного ISO. Для дисков VM нужно достаточно места в выбранном хранилище.

Можно выбрать другой диапазон и дисковое хранилище:

```bash
bash /root/demo-bootstrap.sh --deploy-plan --base-id 300 --bridge-base 301 --storage local-lvm --uplink vmbr0
bash /root/demo-bootstrap.sh --deploy --base-id 300 --bridge-base 301 --storage local-lvm --uplink vmbr0
```

## Сеть

Создаются изолированные мосты vmbr201–vmbr209 без адресов и физических портов. Они добавляются в /etc/network/interfaces и поднимаются отдельно командой ifup. vmbr0 используется как существующий внешний мост ISP; его настройки не меняются. Перед изменениями сохраняется копия сетевой конфигурации. Если есть ожидающие изменения /etc/network/interfaces.new, сначала разберись с ними в панели Proxmox.

| Мост | Назначение |
|---|---|
| vmbr0 | Внешняя сеть ISP |
| vmbr201 | ISP — HQ-RTR |
| vmbr202 | ISP — BR-RTR |
| vmbr203 | HQ-RTR — HQ-SW |
| vmbr204 | HQ-SW — HQ-SRV |
| vmbr205 | HQ-SW — HQ-CLI |
| vmbr206 | BR-RTR — BR-FW |
| vmbr207 | BR-FW — BR-SRV |
| vmbr208 | Служебная карта HQ-RTR |
| vmbr209 | Служебная карта BR-RTR |

EcoRouter получает три e1000: net0 служебный, net1 к ISP, net2 к локальной сети. Остальные машины — virtio. BR-FW: net0 к BR-SRV, net1 к BR-RTR. VLAN-теги Proxmox не назначаются: позже их настраивают внутри гостевых ОС. Межсетевой экран на картах отключён для этой учебной топологии.

## Контроль и восстановление после ошибки

Занятые VMID проверяются по всему кластеру, включая контейнеры. Занятые мосты отклоняются. Скрипт не удаляет и не перезаписывает существующие VM. Повторный запуск после частичного создания не продолжает установку автоматически: он остановится на занятых номерах. Не удаляй машины вслепую; сначала прочитай журнал.

Журнал и список созданных машин сохраняются в /root/demo-deploy.XXXXXXXX. Там также находятся копия сетевой конфигурации, профили и журналы последовательных консолей. Эти файлы имеют доступ только root и могут содержать установочный пароль. После проверки работы можешь удалить секретные профили из этого каталога.

ALT получает частный установочный ISO с профилем в /Metadata и параметром ai. При первом запуске установленной ОС профиль отправляет маркер DEMO_INSTALL_OK в последовательную консоль и выключает VM. Только после получения маркера скрипт отключает и удаляет свой временный ISO, возвращает указанную ОЗУ и оставляет загрузку с диска. Неожиданная остановка или превышение 90 минут оставляет VM и ISO для диагностики. **Наличие маркера не заменяет проверку нормальной загрузки и работы ОС.**

Исходники имеют префикс demo-source- и остаются в local. Локальные SHA256 позволяют обнаружить изменение скачанного файла при повторном использовании; это не подписи производителя. EcoRouter с внешним backing-файлом отклоняется.

Основа ALT автоустановки: [документация ALT Server 11.0](https://docs.altlinux.org/ru-RU/alt-server/11.0/html/alt-server/install-distro--autoinstall--chapter.html) и [параметры запуска](https://docs.altlinux.org/ru-RU/alt-server/11.0/html/alt-server/ch21s02.html). Загрузка: [gdown](https://pypi.org/project/gdown/). Импорт дисков: [Proxmox](https://pve.proxmox.com/wiki/Migrate_to_Proxmox_VE).

## Отдельный режим для существующего стенда

Ниже — прежний скрипт подключения адаптеров. Его --plan/--apply не создают VM и не запускают автоустановку.

# Адаптеры первого модуля — Proxmox

Скрипт подключает карты восьми существующих VM. Не создаёт VM, не меняет диски, гостевые ОС, IP, VLAN внутри ОС и питание машин. На текущем стенде не запускался. Выполнена проверка синтаксиса Bash; это не подтверждает проверку на реальном Proxmox.

## Использование

Скопируй весь каталог на Proxmox, например в /root/proxmox-adapters. Проверь machines.tsv: номера VM и порядок карт должны совпадать с твоим стендом. Названия VM проверяются: ISP, HQ-RTR, HQ-SW (допускается HQ-SV), HQ-SRV, HQ-CLI, BR-RTR, BR-FW, BR-SRV.

```bash
cd /root/proxmox-adapters
bash connect-adapters.sh --plan
```

План ничего не меняет. Перед применением штатно выключи восемь VM. Suspend недостаточен. Скрипт не выключает машины сам и откажется работать с блокировками и ожидающими изменениями.

```bash
bash connect-adapters.sh --apply
```

Существующие модели карт и MAC сохраняются. Новые карты Linux/Ideco имеют модель virtio, EcoRouter — e1000. Bridge устанавливается по таблице. Firewall карты выключается, link_down снимается. Proxmox tag/trunks удаляются: VLAN на HQ настраиваются внутри гостевых ОС. Прочие параметры существующих карт сохраняются. Лишние карты не удаляются: выводится предупреждение. Проверь их отдельно, чтобы лишняя карта не обходила топологию.

## Нужные мосты

Мосты должны уже существовать и быть активными. Создать недостающие можно в home → System → Network → Create → Linux Bridge. vmbr1–vmbr9: без IPv4, шлюза и физических Bridge ports, Autostart включён. vmbr0 — существующий домашний мост; его конфигурацию не менять. На сервере с занятыми vmbr1–vmbr9 используй другие свободные номера и измени machines.tsv. Сам скрипт конфигурацию сети хоста не изменяет.

| Мост | Соединение |
|---|---|
| vmbr0 | Домашняя сеть, внешняя карта ISP |
| vmbr1 | ISP — HQ-RTR |
| vmbr2 | ISP — BR-RTR |
| vmbr3 | HQ-RTR — HQ-SW, trunk VLAN 100/200/999 |
| vmbr4 | HQ-SW — HQ-SRV |
| vmbr5 | HQ-SW — HQ-CLI |
| vmbr6 | BR-RTR — BR-FW |
| vmbr7 | BR-FW — BR-SRV |
| vmbr8 | Служебная карта HQ-RTR |
| vmbr9 | Служебная карта BR-RTR |

В комплекте порядок BR-FW: net0 → BR-SRV, net1 → BR-RTR, по исходному стенду Proxmox. В VMware-методичке порядок другой: это допустимо, если гостевые настройки сопоставлены по MAC. Если на твоей установке карта net0 смотрит к BR-RTR, поменяй порядок мостов для BR-FW в machines.tsv на vmbr6,vmbr7. Проверить MAC/IP в Ideco до применения обязательно.

## Резервная копия

Перед первой записью создаётся /root/demo-adapters-backup.XXXXXXXX. В нём копии конфигураций и restore-nics.sh, который возвращает только изменённые карты. При ошибке изменения могут быть частичными; сначала прочитай ошибку и проверь конфигурацию. Для отката выключи затронутые VM и убедись, что их задачи завершены, затем запусти из своей папки резервной копии:

```bash
bash /root/demo-adapters-backup.XXXXXXXX/restore-nics.sh
```

Не заменяй конфигурации целиком копированием: диски и другие настройки могли измениться после резервной копии.
